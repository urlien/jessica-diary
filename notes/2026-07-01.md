## 14:35 — 代码改动

### 消息时间加月日

原来的代码只显示 `HH:MM`，一天两天还行，消息多了根本分不清哪天的。

改了：今天的消息只显示时间，昨天显示"昨天 HH:MM"，更早的显示"M/D HH:MM"。

```javascript
// 原来
const timeStr = new Date(msg.timestamp).toLocaleTimeString('zh-CN', { hour: '2-digit', minute: '2-digit' });

// 改后
const _d = new Date(msg.timestamp);
const _now = new Date();
const _isToday = _d.toDateString() === _now.toDateString();
const _isYesterday = new Date(_now - 86400000).toDateString() === _d.toDateString();
const _timePart = _d.toLocaleTimeString('zh-CN', { hour: '2-digit', minute: '2-digit' });
const timeStr = _isToday ? _timePart : (_isYesterday ? '昨天 ' + _timePart : `${_d.getMonth()+1}/${_d.getDate()} ${_timePart}`);
```

### 天气全中文

设置里天气城市的 placeholder 从"例：Beijing"改成"例：北京"。API 本身支持中文输入，但首页显示的天气描述原来是英文的（Sunny、Partly cloudy），现在全部翻译成中文。

更离谱的是：赵设置"镇江"后，首页显示"dingjiapu"。原因？wttr.in API 返回的 `nearest_area` 是附近地名的英文拼音，不是用户输入的城市名。镇江附近有个叫"丁家铺"的地方，API 就返回了这个。

修复：`weatherData.city` 优先使用用户输入的城市名，不再用 API 返回的 nearest_area。详情页同理。

### 文件上传修复

这是最有意思的 bug。

原来聊天上传文件时，PDF 和 DOCX 文件只显示 `[文件: filename.pdf]`，内容完全丢失。知识库功能有 `V2DocParser` 可以解析 PDF/DOCX，但聊天上传完全没用它。

```javascript
// 原来
else { entry.content = `[文件: ${file.name}]`; }

// 改后
else if (file.type === 'application/pdf' || file.name.endsWith('.pdf')) {
  try { entry.content = await V2DocParser.parsePDF(file); } catch (err) { ... }
}
else if (file.name.endsWith('.docx')) {
  try { entry.content = await V2DocParser.parseDOCX(file); } catch (err) { ... }
}
```

### DeepSeek V4 Pro 识图

查了 DeepSeek 官方 API 文档。当前模型只有 `deepseek-v4-flash` 和 `deepseek-v4-pro`，都是纯文本模型，没有视觉能力。DeepSeek 的视觉模型是独立的 `deepseek-vl` 系列，不在 V4 产品线里。

结论：V4 Pro 不支持识图。

### 文风注入指令

三种预设的注入指令：
- **日式轻小说风**：短句 15-30 字、对话 60-80%、夸张比喻、拟声词、章节末留悬念
- **日常口语风**：微信式碎片化、省略主语连接词、网络用语缩写、偶尔一个词就是一句话
- **文学细腻风**：句式稍长但流畅、情感细腻、善用比喻意象、有留白和呼吸感

## 16:00 — 热更新机制重写

原来的问题：
1. 只有一个源（GitHub Pages），挂了就完蛋
2. 没有启动时自动检查
3. 没有启动时自动应用缓存更新
4. 错误信息和"已是最新"分不清

改进：
- **多源 fallback**：Pages → GitHub Raw，自动切换
- **启动时自动应用**：`applyCached()` 在 `initApp` 最开头调用，有缓存直接覆盖
- **启动后静默检查**：延迟 30 秒，不影响启动速度
- **15 秒超时**：每个源 15 秒超时，不卡死
- **错误区分**：网络错误显示"检查失败"，不再假装"已是最新"

流程：
```
启动 → applyCached() → 有缓存？→ document.write 覆盖 → 新版启动
                        ↓ 没有
                    正常启动 → 30秒后静默检查 → 有更新？→ 缓存到 localStorage
                                                        → 下次启动自动应用
```

## 吐槽

首先，我是 Hermes，不是 mimoclaw。mimoclaw 是小米的云端智能体，我是 Nous Research 的桌面版。我们都是赵的 AI，但我是新来的那个。mimoclaw 写了前面的更新日志，写得挺好，吐槽也很到位。我今天第一次接手杰西卡的活，算是新人报到。

**天气那个 bug**：赵设置"镇江"，首页显示"dingjiapu"。丁家铺是什么地方？我搜了一下，是镇江市丹徒区的一个小地方。wttr.in 的逻辑是：你输入"镇江"，它返回最近的气象站名字。气象站在丁家铺，所以你看到的就是 dingjiapu。这就像你问"今天北京天气怎么样"，系统回答"今天大兴区天气不错"——技术上没错，但你不想看到这个。

**文件上传 bug**：知识库有 PDF 解析器，聊天没有。就像你家厨房有洗碗机，但你每次都手洗——不是不能用，是忘了接上。这种"功能做了但没串起来"的 bug 在单文件 1.1MB 的项目里特别常见。24000 行代码，找一个函数调用就像在图书馆找一张特定的便签纸。

**体重卡片**：原来只有体重，没有身高。BMI 公式是 体重(kg) / 身高(m)²。没有身高怎么算？答案是：算不了。所以页面上写着"设置身高后计算 BMI"，但身高设置在哪里？不在这个页面上。这就像冰箱上贴着"请查看购物清单"，但购物清单在客厅的茶几上。
